# Kitex v0.16.3 generation and interoperability check

Date: 2026-09-01

This note records the follow-up check after moving this fork's embedded Kitex
generator from `v0.15.4` to the current stable release, `v0.16.3`. The Hertz
codegen module remains `hertz/cmd/hz v0.9.7`, which is the highest available
`hz` release. The main Hertz framework is a separate runtime dependency of the
generated application and is not embedded by cwgo.

The protobuf `google.golang.org/protobuf` replace pin remains unchanged because
it is still required by `hz v0.9.7`.

## Toolchain under test

| Component | Version |
|---|---:|
| cwgo fork | local `v0.1.2` build |
| embedded Kitex generator/runtime dependency | `v0.16.3` |
| hz codegen | `v0.9.7` |
| thriftgo | `v0.4.5` |
| old upstream cwgo | archived `v0.1.2` |
| old embedded Kitex | `v0.9.1` |
| Go | `1.26.3` |

The same minimal protobuf `GreetService Hello` fixture from the v0.15.4 note
was used. The fixture and runner live under `test/compat/kitex-greet/`.

## Commands

```bash
go test ./...
go build -o bin/cwgo .

GOSUMDB=off \
OLD_CWGO=/path/to/old-cwgo-v0.1.2 \
NEW_CWGO=/path/to/this-fork/bin/cwgo \
NEW_KITEX_VERSION=v0.16.3 \
NEW_FULL_KITEX_VERSION=v0.16.3 \
COMPAT_WORK_ROOT=/path/to/cwgo/output/compat/kitex-greet/v0163-manual \
  ./test/compat/kitex-greet/run.sh
```

The run writes all generated projects under the repository-local, ignored
`output/` directory. It intentionally avoids `/tmp`.

## Results

The cwgo module builds and all unit tests pass with Kitex `v0.16.3`.

Both the upstream-generated and fork-generated full greet projects pass:

```bash
go mod tidy
go build ./...
go test ./...
```

The generated `kitex_gen` output for `v0.15.4` and `v0.16.3` is the same for
this fixture except version markers:

- `// Code generated by Kitex v0.16.3. DO NOT EDIT.`
- `KiteXGenVersion: "v0.16.3"`

As with `v0.15.4`, protobuf output continues to use `prutal` and does not emit
FastPB methods. The fork still forces `NoFastAPI=true` for protobuf.

The runtime interop matrix uses real TCP unary RPCs, 20 calls per cell:

| Client | Server | Result |
|---|---|---|
| Kitex `v0.9.1` | Kitex `v0.9.1` | 20/20 OK |
| Kitex `v0.16.3` | Kitex `v0.9.1` | 20/20 OK |
| Kitex `v0.9.1` | Kitex `v0.16.3` | 20/20 OK |
| Kitex `v0.16.3` | Kitex `v0.16.3` | 20/20 OK |

The runner prints `MATRIX_OK` only after all four cells pass.

## Scope

This remains a minimal protobuf unary RPC regression gate. Streaming, custom
transports, mux, gRPC transport, discovery, retries, circuit breaking, and
business handlers still need a real project smoke test before production use.
